# 腾讯青云｜AI Infra 一年学习计划

这是黄子昱面向腾讯青云计划 AI 开发 / AI Infra 方向建立的持续学习仓库。

## 学习目标

- 在一年内完成 C++、数据结构与算法、Linux、AI 推理部署和工程实践的系统积累。
- 以每天约 30 分钟、每周一个可验收目标的节奏推进。
- 通过小项目和代码记录，逐步接近 AI Infra / 大模型推理实习岗位要求。

## 每日记录结构

每次学习结束后，按照以下内容记录：

1. 今日主题与学习目标
2. 核心知识点
3. 代码例子
4. 今日练习与作答情况
5. 易错点
6. 与 AI Infra / mini-TRT 的联系
7. 掌握程度与待巩固内容
8. 下一次学习任务

## 目录

- `daily/`：每日学习记录
- `exercises/`：完整代码模块实战题、提交记录和测试说明
- `projects/`：阶段性项目
- `notes/`：专题笔记
- `progress.md`：整体进度看板

## 项目目录规范

每个阶段性项目单独放在 `projects/项目名/` 下，至少包含：

```text
项目名/
├── README.md       # 项目目标、运行方法和结果
├── src/            # 源代码
├── tests/          # 测试代码
└── docs/           # 设计说明和实验记录
```

项目优先遵循“能运行、可解释、可复现”的原则。每完成一个阶段，就在项目的 `README.md` 中记录功能、测试结果和下一步计划。

## 代码实战流程

学习过程中会逐步加入需要独立完成的完整 C++ 模块。每道题按照以下流程进行：

1. 先阅读 `exercises/题目目录/README.md`，只看需求、接口和测试样例。
2. 独立编写 `.cpp` 文件，并把代码发给我或上传到对应题目目录。
3. 我帮助你编译、测试和定位问题，但不会在你提交前直接给出完整答案。
4. 复盘通过后，将最终版本、测试结果和易错点归档到仓库。

这样仓库中既有知识讲解，也有可以运行和验证的代码作品。

## 讨论结果同步规则

每次学习讨论结束后，都留下可见的 GitHub 记录：

1. 每日学习内容和验收结果写入 `daily/日期-主题.md`。
2. 实战题的概念解释、疑问、错误原因、代码审查和优化结论写入对应题目的 `notes.md`。
3. 完成并验收的代码写入对应题目的 `submission.cpp`。
4. 只有完成验收后，才更新 `progress.md`。
5. 每次记录都写明下一次学习任务，保证后续学习从上次结果继续。

记录重点不是复制聊天内容，而是保存真正掌握的概念、可复现的代码、测试结果和仍需巩固的问题。
